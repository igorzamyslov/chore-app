# Spec: Local Data Layer (drift/SQLite)

*Local-first storage for v1 (no backend yet). Every convention below is
chosen so a future Supabase/PowerSync sync layer can be added WITHOUT a
schema rewrite: UUID text PKs generated client-side, `updated_at` on every
mutable row, soft deletes on user-visible entities, no server-generated
values.*

## Placement

| What | Where |
|---|---|
| Table definitions | `lib/data/db/tables.dart` |
| Type converters | `lib/data/db/converters.dart` |
| Database class | `lib/data/db/app_database.dart` (+ generated `app_database.g.dart`, checked in) |
| Repositories | `lib/data/repositories/<name>_repository.dart` |
| Tests | `test/data/...` mirroring lib structure |

Repositories take `AppDatabase` (and, where noted, an id/clock function) via
constructor — NO Riverpod, NO Flutter imports in `lib/data/` (drift and
drift_flutter are allowed; the app_database.dart may import drift_flutter
for the open helper, kept in a separate `openConnection()` function so tests
can construct `AppDatabase(NativeDatabase.memory())`).

## Conventions (apply to every table unless stated)

- **id**: `TEXT` primary key, UUIDv4. Generated by the caller/repository via
  an injected `String Function() newId` (default: `const Uuid().v4` from
  package:uuid) — injectable so tests can use deterministic ids.
- **created_at / updated_at**: `TEXT`, ISO-8601 UTC with milliseconds
  (`DateTime.toUtc().toIso8601String()`). Repositories set both on insert
  and bump `updated_at` on every update, using an injected
  `DateTime Function() nowUtc` (default `() => DateTime.now().toUtc()`;
  tests inject fixed values). Stored as text (not int) for painless
  Postgres migration.
- **deleted_at**: `TEXT` nullable — soft delete on `categories`, `chores`,
  `shopping_items`. All queries/watches filter `deleted_at IS NULL` unless
  the method name says otherwise. Hard DELETE is never exposed except
  `chore_occurrences` cascade noted below.
- **PlainDate columns**: `TEXT` `yyyy-mm-dd` via a `TypeConverter<PlainDate,
  String>` using `PlainDate.parse`/`toIso8601`.
- **Recurrence column**: `TEXT` JSON via `TypeConverter<Recurrence, String>`
  wrapping `jsonEncode(r.toJson())` / `Recurrence.fromJson(jsonDecode(...))`.
- **Enum columns**: `TEXT` storing the Dart enum `.name`. New Dart enums
  defined in `tables.dart`: `MemberRole { admin, member }`,
  `CategoryKind { chore, shopping }`,
  `AssignmentMode { fixed, rotation, anyone }`,
  `OccurrenceStatus { pending, done, skipped, missed }`.
- Foreign keys: declared with `references(...)`; enable
  `PRAGMA foreign_keys = ON` in `MigrationStrategy.beforeOpen`.

## Tables

**households**: id PK, name TEXT NOT NULL, created_at, updated_at.

**members**: id PK, household_id → households.id, name TEXT NOT NULL,
color INTEGER NOT NULL (ARGB), role TEXT NOT NULL (MemberRole),
user_id TEXT NULL (future auth mapping), created_at, updated_at.
*v1 note: members are local profiles (no accounts) — a family shares one
device-local household until sync lands.*

**categories**: id PK, household_id → households.id, kind TEXT NOT NULL
(CategoryKind), name TEXT NOT NULL, icon TEXT NOT NULL (Material Symbols
identifier, e.g. `cleaning_services`), color INTEGER NOT NULL,
sort_order INTEGER NOT NULL DEFAULT 0, created_at, updated_at, deleted_at.

**chores**: id PK, household_id → households.id, title TEXT NOT NULL,
notes TEXT NULL, category_id TEXT NULL → categories.id,
recurrence TEXT NULL (Recurrence JSON; NULL = one-off chore),
start_date TEXT NOT NULL (PlainDate), assignment_mode TEXT NOT NULL,
paused_at TEXT NULL (timestamp; non-null = paused),
created_by TEXT NULL → members.id, created_at, updated_at, deleted_at.

**chore_assignees**: chore_id → chores.id, member_id → members.id,
position INTEGER NOT NULL (0-based rotation order). Composite PK
(chore_id, member_id). For `fixed` mode: exactly one row. For `rotation`:
2+ rows ordered by position. For `anyone`: zero rows.

**chore_occurrences**: id PK, chore_id → chores.id, due_date TEXT NOT NULL
(PlainDate), status TEXT NOT NULL default pending,
assigned_member_id TEXT NULL → members.id, completed_by TEXT NULL →
members.id, closed_on TEXT NULL (PlainDate the user closed it),
created_at, updated_at. Index on (chore_id, status) and (status, due_date).
Occurrences are hard-deleted only via chore soft-delete cleanup (below).

**shopping_items**: id PK, household_id → households.id, name TEXT NOT NULL,
quantity_note TEXT NULL, category_id TEXT NULL → categories.id,
added_by TEXT NULL → members.id, checked_at TEXT NULL (timestamp; non-null
= checked), created_at, updated_at, deleted_at.

`schemaVersion` = 1. No legacy migrations. `beforeOpen` also runs
`onCreate`-seeded data? NO — seeding is a repository concern (below), not a
migration concern.

## Repository API (exact signatures)

All `watch*` methods return drift streams that emit on every relevant
change. All write methods bump `updated_at`. "Active" = `deleted_at IS
NULL`.

### HouseholdRepository
```dart
Future<Household> ensureLocalHousehold();
  // Returns the single existing household, or creates one named
  // 'My household' with one admin member named 'Me' (color: 0xFF26A69A).
  // Idempotent. This is the v1 bootstrap.
Stream<List<Member>> watchMembers(String householdId);   // ordered by name
Future<Member> addMember(String householdId,
    {required String name, required int color,
     MemberRole role = MemberRole.member});
Future<void> renameMember(String memberId, String name);
```

### CategoryRepository
```dart
Future<void> seedDefaults(String householdId);
  // Inserts the default chore + shopping category sets below, only if the
  // household has zero categories of that kind (idempotent per kind).
Stream<List<Category>> watchCategories(String householdId, CategoryKind kind);
  // active only, ordered by sort_order then name
Future<Category> createCategory(String householdId, {required CategoryKind
    kind, required String name, required String icon, required int color,
    int sortOrder = 0});
Future<void> updateCategory(String id,
    {String? name, String? icon, int? color, int? sortOrder});
Future<void> softDeleteCategory(String id);
  // sets deleted_at AND nulls category_id on active chores/shopping items
  // referencing it (one transaction).
```

Default chore categories (icon = Material Symbols name):
Cleaning/`cleaning_services`, Kitchen/`skillet`, Laundry/`local_laundry_service`,
Garden/`yard`, Pets/`pets`, Maintenance/`build`, Errands/`directions_car`.
Default shopping categories: Produce/`nutrition`, Dairy/`egg`,
Meat & Fish/`set_meal`, Bakery/`bakery_dining`, Frozen/`ac_unit`,
Drinks/`local_cafe`, Household/`home`, Other/`shopping_bag`.
Colors: pick 8 distinct muted ARGB values (exact values implementer's
choice, documented as constants).

### ChoreRepository
```dart
Future<Chore> createChore({
  required String householdId, required String title, String? notes,
  String? categoryId, Recurrence? recurrence, required PlainDate startDate,
  required AssignmentMode assignmentMode,
  List<String> assigneeMemberIds = const [],  // order = rotation order
  String? createdBy,
});
  // Validates: fixed => exactly 1 assignee; rotation => >= 2; anyone => 0.
  // Throws ArgumentError otherwise. Inserts chore + assignee rows in one
  // transaction. Does NOT create occurrences (service layer's job).
Future<void> updateChore(String id, {String? title, Object? notes = _unset,
    Object? categoryId = _unset, Object? recurrence = _unset,
    PlainDate? startDate, AssignmentMode? assignmentMode,
    List<String>? assigneeMemberIds});
  // _unset sentinel pattern so null can be written; same validation.
Future<void> softDeleteChore(String id);
  // sets deleted_at + hard-deletes its PENDING occurrences (history rows
  // done/skipped/missed are kept).
Future<void> setPaused(String id, {required bool paused});
Stream<List<ChoreWithDetails>> watchActiveChores(String householdId);
  // ChoreWithDetails = chore + ordered assignee member ids + category.
Future<ChoreWithDetails?> getChore(String id);

// Occurrence primitives (used by the service layer):
Future<ChoreOccurrence> insertOccurrence({required String choreId,
    required PlainDate dueDate, String? assignedMemberId});
Future<void> closeOccurrence(String occurrenceId, {required
    OccurrenceStatus status, required PlainDate closedOn,
    String? completedBy});
  // status must be done/skipped/missed; throws ArgumentError on pending.
Future<ChoreOccurrence?> pendingOccurrenceOf(String choreId);
Future<void> deletePendingOccurrences(String choreId);
Future<ChoreOccurrence?> latestClosedOccurrence(String choreId);
  // most recent by closed_on then due_date, any non-pending status.
Stream<List<OccurrenceWithChore>> watchPendingOccurrences(String householdId);
  // pending occurrences of active, unpaused chores joined with chore +
  // category + assigned member, ordered by due_date then title.
```

### ShoppingRepository
```dart
Stream<List<ShoppingItemWithCategory>> watchActiveItems(String householdId);
  // active only, both checked and unchecked, ordered: unchecked first,
  // then by category sort_order, then name.
Future<ShoppingItem> addItem(String householdId, {required String name,
    String? quantityNote, String? categoryId, String? addedBy});
Future<void> updateItem(String id, {String? name, Object? quantityNote =
    _unset, Object? categoryId = _unset});
Future<void> setChecked(String id, {required bool checked});
Future<void> clearChecked(String householdId);
  // soft-deletes all checked active items.
```

## Testing requirements

In-memory DB per test (`AppDatabase(NativeDatabase.memory())`), injected
deterministic `newId` (counter-based) and `nowUtc` (fixed, advancing when a
test needs updated_at ordering). Cover at minimum:

1. ensureLocalHousehold idempotence (2 calls → 1 household, 1 member).
2. seedDefaults: correct counts per kind; idempotent; re-seeds chore kind
   if only shopping kind exists (per-kind independence).
3. Converters round-trip PlainDate + every Recurrence combo through a real
   insert/select; invalid persisted JSON surfaces as a thrown error on read.
4. createChore validation matrix (fixed/rotation/anyone × 0/1/2 assignees).
5. updateChore: notes/category/recurrence settable AND nullable via
   sentinel; assignee list replacement preserves given order.
6. softDeleteChore: disappears from watchActiveChores, pending occurrence
   deleted, closed occurrences retained.
7. softDeleteCategory: chores/items referencing it get category_id = NULL,
   category vanishes from watches; other categories untouched.
8. Occurrence primitives: closeOccurrence rejects pending status;
   latestClosedOccurrence ordering; pendingOccurrenceOf ignores closed.
9. watchPendingOccurrences: excludes paused chores, soft-deleted chores,
   non-pending occurrences; ordering by due_date then title; stream emits
   when a chore is paused (reactive join).
10. Shopping: ordering contract (unchecked first, category sort_order,
    name); setChecked toggling; clearChecked only removes checked ones;
    updated_at bumped on every mutation (assert via advancing nowUtc).
11. FK enforcement smoke: inserting an occurrence for a nonexistent chore
    throws.

Same done-criteria as always: `dart format` clean, `flutter analyze
--fatal-infos --fatal-warnings` clean, `flutter test` fully green.
Generated `*.g.dart` files are committed; regenerate with
`dart run build_runner build --delete-conflicting-outputs`.
