# UX audit — misplaced functions & unreachable states (2026-08-01)

Requested by Igor after round 3: systematically find (1) functions not
located where a user will look for them (the categories-in-settings
class) and (2) states you cannot reach or cannot escape (the
can't-remove-a-user class). Method: walked every screen and every
entity's lifecycle (create/read/update/delete/undo) against the code;
every finding below was verified in source, not assumed. Decisions
follow the standing "decide and document" instruction.

## Dimension 2 — unreachable / stuck states (ranked by severity)

### A1. Members cannot be deleted — THE reported dead end (P0)
`manage_members_screen.dart` ships no delete affordance (a documented
v1 scope cut), and the local `Members` table has no `deletedAt` column
at all (the server's `members.deleted_at` exists and is even
UPDATE-granted — the client just never caught up). The bootstrap-"Me"
zombie, a duplicate created by a mistaken "I'm new here", a typo'd
member — none of them can ever be removed.
**Decision:** member soft-deletion, client schema **v9** (`deletedAt`
on Members + mapper/pull/push wiring — the P3 engine's granted-columns
members update already covers `deleted_at` server-side). Scope guard:
only UNCLAIMED members (no `userId`) are deletable — removing a
claimed profile is "kicking a person" and belongs to the sync spec's
P4 with role enforcement. Cannot delete the last remaining member.
Deleting the acting member is allowed (the stored-id-else-first-admin
fallback already handles it). Referential handling, stated in the
confirm dialog: rotation chores drop them from the order (existing
next-rotation fallback already tolerates it; if <2 assignees remain
the chore converts to fixed/anyone accordingly), fixed chores convert
to 'anyone', their pending assignments become unassigned; history rows
(completedBy) keep pointing at the soft-deleted row so "who did what"
survives.

### A2. Household cannot be renamed (P1)
"My household" is seeded at creation and shown in the linked subtitle
("Synced with My household") with no rename UI anywhere. Server UPDATE
on `households` is granted; sync propagates it.
**Decision:** editable household name row at the top of the Members
screen (`members.household.rename`).

### A3. Invites cannot be revoked (P1, security-adjacent)
`household_invites.revoked_at` exists server-side and UPDATE is
granted, but no client surface uses it. A code pasted into the wrong
chat stays redeemable for 7 days with no escape.
**Decision:** minimal and sufficient — creating a new invite revokes
all previous active ones (one live code per household). "Escape" =
regenerate. No list UI needed.

### A4. The archive file is a promise without a mechanism (P1 → roadmap)
The join flow's copy says the old household is "kept only in an
archive file", implying restorability — but nothing can read an
archive back in (no import/restore feature exists). Export has the
same property (fine for portability, misleading as backup).
**Decision:** "Restore from backup" joins the P4 cluster (import =
parse `format:1` envelope + the join flow's replace machinery). Until
then the join sheet's copy must not over-promise: adjust to "saved to
a backup file on this device" (drop wording that implies in-app
reversal). Copy fix now, feature later.

### A5. Signed out while linked: engine spins on 401s (P2)
`syncEngineProvider` gates on configured+linked but NOT on
signed-in: after sign-out on a linked device every push/pull fails
silently forever (no data harm; battery/log noise; confusing Account
section — sign-in form with no hint the device is linked).
**Decision:** engine also requires a signed-in user (watch
`currentAuthUserProvider`); Account section's signed-out state gains a
one-line "This phone is linked to <household> — sign in to keep
syncing" hint when linked (`settings.account.signedOutLinked`).

### A6. "Reset app data" copy is stale once synced (P2, copy-only)
The double-confirm says "There is no cloud backup — this cannot be
undone", which is now FALSE on a linked device (the household lives on
the server; reconnect restores it — verified live today).
**Decision:** conditional copy — linked devices get "Your household
stays online; this phone disconnects from it. You can reconnect by
signing in again." Unlinked devices keep the existing warning.

### Escapes that already exist (verified, no action)
Mistaken adopt → Settings join replaces local ✓ (orphan server
household remains — P4 cleanup). Wrong account → sign out ✓. Deleted
category/chore/item → confirmed-destructive or undo-snackbar ✓.
Dismissed digest preprompt → Settings toggle ✓. Reset while linked →
welcome gate + reconnect (coherent after onboarding v2) ✓.

## Dimension 1 — functions not where the user looks

### B1. Filtered-empty state lies (P1)
With a member/category filter active and nothing matching, the list
shows the unqualified "No chores pending — nice work!" praise
(verified: `_ChoresEmptyState` is filter-blind). User conclusion:
"my chores are gone."
**Decision:** when a filter is active and hides everything, show a
distinct state: "Nothing here for this filter" + a "Show everything"
action (`chores.empty.filtered`, `chores.filter.clear`); filter icons
get an active-state badge.

### B2. Can't add a member from where members are picked (P1)
Chore form assignee chips: if the person is missing, the user must
abandon the form → Settings → Members → add → return → re-enter
everything. Same class as categories-in-settings.
**Decision:** trailing "add member" chip in the assignee picker
(`chore_form.assignee.add`) opening the existing member sheet inline;
picker refreshes with the new member selectable. The acting-member
switcher sheet gains a "Manage members" row (`acting.manage`).

### B3. Invite is invisible at the moment it matters (P1)
After adopting, the natural next step is inviting the family — but the
affordance hides in Settings→Members. The Account section's linked
state says "Synced with <household>" and offers nothing to do.
**Decision:** linked Account tile gains an inline "Invite a member"
action (`settings.account.invite`) opening the existing invite sheet.

### Already addressed elsewhere
Categories → inline picker entry (in flight). Registration/join
discoverability → onboarding v2 welcome gate (in flight). Export
placement → Data section (shipped).
